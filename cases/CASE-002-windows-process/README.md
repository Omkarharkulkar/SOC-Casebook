# CASE-002 — Suspicious Windows Process Execution

- **Status:** Analysis complete
- **Investigation type:** Public Windows event-log sample analysis
- **Severity:** Medium detection
- **Verdict:** Suspicious process execution observed; compromise not confirmed
**Analyst:** Omkar Harkulkar

## 1. Overview

This case examines a Windows Sysmon EVTX sample containing process creation events. The objective was to review the process activity, identify unusual parent-child relationships, and check whether available detection rules generated relevant alerts.

Hayabusa was used to generate event metrics and a detection timeline. Its built-in Sigma rules identified a medium-level alert related to FTP-based command execution.

The available evidence supports further investigation of the process activity. It does not confirm successful file transfer, payload execution, or system compromise.

## 2. Objective

- Review Windows process creation events.
- Identify unusual process relationships.
- Examine the detection generated by Hayabusa.
- Understand what the available events establish and what remains unverified.
- Document suitable SOC L1 investigation steps.

## 6. Timeline Analysis

Hayabusa produced four informational process-execution entries and one additional medium-level detection. The medium alert is attached to an event already represented by an informational entry, so there are four unique events, not five.

| Record ID | Timestamp (+05:30) | Observed activity | Detection |
|---|---|---|---|
| 16511 | 22:50:01.980 | Explorer started Command Prompt | Proc Exec — Informational |
| 16512 | 22:50:31.183 | Command Prompt started Python from a WinPwnage-related directory | Proc Exec — Informational |
| 16513 | 22:50:49.443 | FTP started Command Prompt using a script-related option | Proc Exec — Informational; FTP alert — Medium |
| 16514 | 22:50:49.458 | Command Prompt started Windows Calculator | Proc Exec — Informational |

The events show a sequence of process creation activity over approximately 47.5 seconds.

The FTP-related event is notable because Hayabusa generated a medium-level detection for it. The subsequent Calculator process is part of the recorded process sequence, but its presence alone does not establish malicious impact.

## 7. Detection Analysis

**Detection:** Potential Arbitrary Command Execution Via FTP.EXE

- Detection source: Hayabusa built-in Sigma rule
- Rule ID: `086262f5-1aee-ce11-2ddf-4692b9e51b3e`
- Severity: Medium
- Rule status: Test
- Event record: 16513
- Event ID: 1

The rule checks Windows process-creation activity involving FTP and its parent-child process relationships.

For record 16513, the match was through the rule's FTP parent-process condition. The event shows FTP as the parent of Command Prompt. The match should not be described as satisfying every child-process selection in the rule.

The rule is labelled `test` in its metadata. Its alert is a useful investigation lead, but it is not proof of compromise.

## 8. Findings

1. The EVTX sample contains four Sysmon process-creation events.
2. The events show a short sequence involving Explorer, Command Prompt, Python, FTP, and Calculator.
3. Hayabusa generated four informational process-execution entries.
4. A medium-level FTP-related alert was generated for record 16513.
5. The alert matched through the FTP parent-process condition.
6. The available sample does not establish whether a file transfer succeeded or whether any payload was executed.
7. No evidence in the reviewed events confirms system compromise or impact.

## 9. Verdict and Reasoning

**Verdict: Suspicious process execution observed — further investigation required.**

The FTP-related medium alert and surrounding process activity are sufficient to justify investigation. However, the available evidence is limited to four process-creation events from one public sample.

There is no supporting evidence here to confirm successful transfer, persistence, data access, or compromise. Therefore, the case does not conclude that the host was compromised.

## 10. Recommended SOC L1 Actions

If similar activity appeared in a production environment:

1. Preserve the relevant Sysmon and Windows event logs.
2. Review the full process tree, including parent and child process details.
3. Examine surrounding network, file, and authentication events.
4. Check whether the process activity was expected and authorized.
5. Search for related activity on other hosts and accounts.
6. Escalate to the appropriate security team if corroborating evidence is found.
7. Follow the organization's incident-response policy when deciding whether containment is necessary.

Do not treat the alert alone as sufficient justification for a confirmed-compromise conclusion.

## 11. Limitations

- Only one public EVTX sample was examined.
- No separate Windows lab capture was available for comparison.
- The original activity context was not independently verified.
- The sample contains only four Sysmon process-creation events.
- The detection rule is marked `test`.
- The reviewed events do not establish successful file transfer, payload execution, or impact.
- No additional endpoint, network, or authentication telemetry was available for correlation.

## 12. Conclusion

This investigation demonstrated how Sysmon process-creation events can be reviewed using Hayabusa and how a built-in Sigma detection can identify suspicious FTP-related process activity.

The alert provides a useful lead for a SOC analyst, but the limited evidence does not confirm compromise. Additional endpoint and network telemetry would be required to determine the full context and impact.
